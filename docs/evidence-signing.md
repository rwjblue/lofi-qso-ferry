# Direct LoTW signing evidence

Updated 2026-10-25. This is local compatibility evidence, not ARRL acceptance. Production remains on release `f2c41cb3` and signing profile 2; the local profile 3 changes described below await deployment.

The Worker imports legacy RC2/3DES and current PBES2/AES PKCS#12 files, verifies their integrity MAC, requires exactly one matching RSA key/certificate, extracts LoTW callsign/DXCC and separate QSO authorization dates, then normalizes to PKCS#8. Import is bounded at 256 KiB, eight certificates, 100,000 KDF iterations, 12,000 decoded nodes and 32 inspected levels. Signing requires current certificate validity and an unrevoked serial status checked within 24 hours. Ferry leaves certificate-authority validation to LoTW when it processes the signed upload; local import does not prove ARRL issuance or upload acceptance. Passwords and original PKCS#12 bytes are not part of normalized credentials.

The local signing profile is `ferry-lotw-v2-us-ca-3`. It preserves profile 2's lossless four/six/eight-character station grids and existing signed-field order, but excludes FST4W as a direct mode or submode for new signing: pinned native TQSL configuration 11.34 has no verified mapping for it. The remaining 18 supported modes and 29 bands agree with that configuration; this is configuration agreement, not an execution test of every mode/band combination. SSB with USB/LSB ADIF submodes uses the supported SSB parent mapping, while FT4 remains exact. Unknown modes are never silently dropped or mapped to DATA.

The separate `lotwIdentityMode` helper retains the stable exact FST4W identity used by existing claims and recovery/readback; that preservation grants no new signing authority. Unsupported or stale-profile prepared dispatch remains held. FST4W is also excluded from LoTW historical DATA grouping, with local historical matcher version 6 and candidate policy version 2 invalidating older comparison results. These local changes do not describe the currently deployed profile.

US and Canadian subdivisions and the conservative explicit mode/band set are supported. Other subdivision schemes and satellite names not yet accepted by ARRL require configuration evidence before rollout. US county syntax is checked, but the full current ARRL county enumeration still requires rollout validation. Mixed callsigns, DXCC or locations must be separate artifacts. Each artifact carries exact source UUID/generation members, credential version and configuration version. The coordinator durably encrypts it before dispatch. The adapter limits an artifact to 100 contacts; initial orchestration can use one contact.

The field order and legacy RSA SHA-1 wire signature were compared with [Wavelog's pinned direct signer](https://github.com/wavelog/wavelog/blob/7f8eef4de94c674f73c6859ed4e0b0247f68dcd9/application/views/lotw_views/adif_views/adif_export.php) and [certificate import/status handling](https://github.com/wavelog/wavelog/blob/7f8eef4de94c674f73c6859ed4e0b0247f68dcd9/application/controllers/Lotw.php). Adapted ordering retains its MIT notice in `fixtures/signing/WAVELOG-LICENSE.txt`. Application hashes remain SHA-256. `fixtures/signing/vector.json` has exact canonical bytes and an independent `openssl dgst -sha1` signature using the explicitly synthetic private key. No personal key or contact was used.

## Station grid precision

Ferry accepts one ASCII Maidenhead grid with exactly four, six or eight characters, validates each coordinate range and uppercases letters. It preserves every character in both the signed `tSTATION.GRIDSQUARE` and canonical signature input. For example, source `fn31pr12` produces `<GRIDSQUARE:8>FN31PR12`; the original source object remains unchanged. It does not truncate to six characters, synthesize missing precision, emit an unverified extension field, or accept multi-grid locations under this profile. Two-, ten- and twelve-character grids remain outside Ferry's supported profile.

The primary evidence is the [TQSL 2.8.6 release linked by ARRL](https://www.arrl.org/tqsl-download), inspected from the [released source archive](https://sourceforge.net/projects/trustedqsl/files/tqsl-2.8.6.tar.gz/download). The downloaded archive SHA-256 is `182e5f2ac35a3db8b409b45d96505e6bd265ae4668ed064754209c4b8e7bdf37`. In that release:
- `src/location.cpp:626` (`tqsl_verifyGridFormat`) validates single-grid lengths through twelve characters when its `twelve` flag is true, including the numeric seventh/eighth characters.
- `src/tqslconvert.cpp:1670` passes that flag for a single `MY_GRIDSQUARE`; the setter at `src/location.cpp:4112` retains the full value. The station-location UI likewise passes the single-grid flag at `apps/tqslwiz.cpp:1058`.
- `src/location.cpp:3692` (`tqsl_getGABBItSTATION`) writes the full stored value and its actual length. `make_sign_data` at line 752 appends the complete grid to the signature input; `src/config.xml:7837` includes `GRIDSQUARE` in the LoTW v2 station signature order.

The older [Trusted GAbbI specification, version 0.25 from 2002](https://www.rickmurphy.net/trustedqsl.org/Trusted_GAbbI.pdf), lists a six-character maximum. It does not describe the released TQSL 2.8.6 single-grid path above. The pinned Wavelog signer also writes the complete station grid with its actual length and appends the complete value to its signature input. [ARRL's submission contract](https://lotw.arrl.org/lotw-help/developer-submit-qsos/) identifies `MY_GRIDSQUARE` as station-location input, and its [query contract](https://lotw.arrl.org/lotw-help/developer-query-qsos-qsls/) returns the uploaded own-station grid as `MY_GRIDSQUARE`. No separate grid-extension field is needed for this representation.

`tests/signing.test.ts` fixes the eight-character canonical bytes and an independent OpenSSL RSA/SHA-1 signature generated with the existing synthetic key. It verifies that the complete grid appears in the signed artifact and that truncating the grid or changing its final digit invalidates that signature. The original six-character vector remains unchanged. `tests/lotw-grid.test.ts` verifies exact eight-character readback, malformed-grid rejection and source preservation. A six-character prefix, missing grid, different final digits or a longer grid cannot acknowledge an eight-character upload, even if the remote record is confirmed.

Historical association has a separate deployed policy: valid nested 2/4/6/8-character grids may agree under the inclusive ±30-minute matcher when every other location, uniqueness, coverage and ownership check passes. Both original grid values remain intact and the association remains blocked from upload. This does not acknowledge a newly transmitted artifact or relax its exact full-grid readback. See [LoTW evidence](evidence-lotw.md).

The released-source inspection and the native synthetic comparison below establish local representation evidence. Exact eight-character server readback still needs the authorized rollout check below; exports remain disabled.

## Submission and readback

[ARRL submission documentation](https://lotw.arrl.org/lotw-help/developer-submit-qsos/) defines signed uploads and `.UPL.` accepted/rejected comments. The real adapter sends gzip TQ8 as multipart `upfile` to the fixed HTTPS upload endpoint. It reports queue acknowledgement as `submitted`; missing responses, transport errors, redirects and unexpected responses remain `uncertain` and cannot authorize blind retry. Both the deployment export gate and explicit live-write authorization must pass before dispatch.

[ARRL query documentation](https://lotw.arrl.org/lotw-help/developer-query-qsos-qsls/) defines accepted unconfirmed records, own-station detail, receive-time watermarks, and the current EOF marker. Query uses `qso_qsl=no`, explicit `qso_qsorxsince`, `qso_withown=yes` and `qso_mydetail=yes`. It streams at most 2 MiB per inclusive 32-day partition; overflow, HTML, missing EOH/EOF, inconsistent NUMREC, malformed identities or truncation cannot establish coverage or absence. Callers must split and complete larger query scopes. Uncertain-result readback scopes the contact's UTC day and station/worked calls; first-insert absence instead requires the preceding, current and following UTC dates, without band/mode filtering. Oversized responses remain held. A receive checkpoint applies only to the identical query, and resumption should overlap the inclusive timestamp boundary.

Readback frequency has five decimal MHz places (10 Hz); finer transmitted precision is explicitly `insufficient_evidence`, so an old rounded record cannot acknowledge a one-Hz correction. Acknowledging a transmitted artifact requires exact seconds, unique identity and the supported readback-visible station/contact projection; minute-only history cannot prove that exact receipt. Accepted/unconfirmed and confirmed remain separate; seeing an older identity with the wrong location/frequency does not acknowledge a correction. County readback is compared with ADIF `state,county` representation. This representation and legacy/current live certificate formats still need scoped vendor readback evidence.

## Connection and account identity

The connection API stores `{signingCredentials: [...], query?: {username,password}}` only inside the encrypted credential envelope. A verified LoTW website query username establishes a stable `query:<username>` logical destination. Subsequent imports for that same query account merge certificates by exact callsign/DXCC, replacing a renewed pair in the active credential version and preserving the destination ledger. Current v1 limits each account to eight station certificates. The original certificate versions remain available for immutable in-flight attempts until bounded retention expires; revoked connections delete credential ciphertext immediately and cancel unsent work.

Without query credentials, a certificate cannot establish LoTW website account identity. The connection therefore uses a distinct `station:<CALL>:<DXCC>` destination. Adding verified query credentials creates a separate logical destination and requires read-only reconciliation; it cannot silently inherit unverified station mappings. Different active routes that overlap a callsign/DXCC must be blocked as ambiguous by orchestration. Certificate imports alone perform no QSO signing or submission. `needs_verification` imports remain inactive until certificate-date, serial-status and applicable login problems are resolved. An old local trust flag does not block a usable saved credential. Certificate metadata alone does not establish ARRL issuance; signed-upload acceptance remains authoritative.

Connection tests exercise two synthetic certificates on one verified query account, renewal without destination replacement, no-write LoFi/QRZ verification, session freshness/CSRF, cross-tenant requests, credential encryption, revocation, and transaction guards that reject a session revoked during a vendor read. The fixture tests do not establish live account access. Later bounded read-only checks verified QRZ STATUS field names and existing LoTW query access; see [live read evidence](evidence-live-readonly.md).
